## Запуск навчання

Скрипт `train.py` підтримує налаштування основних гіперпараметрів через аргументи командного рядка:

* `--workspace` — назва workspace в Roboflow для датасету
* `--project` — назва проєкту в Roboflow для датасету
* `--version` — номер версії датасету в Roboflow
* `--rf_key` — Roboflow API-ключ (за замовчуванням: береться з файлу .env)
* `--repo_url` — URL поточного репозиторію GitHub для датасету 
* `--eval_path` — шлях до кореневої папки датасету для тестування (за замовчуванням: None та тестується на валідаційній вибірці тренувальної вибірки. **УВАГА, бути папка valid**)
* `--multi_class` — тренувати на оригінальних багатьох класах (підвидах); якщо не вказано, об'єднує всі в один загальний клас bird
* `--epochs` — кількість епох для тренування (за замовчуванням: 10)
* `--batch` — розмір батчу (за замовчуванням: 16)
* `--img_size` — розмір зображення для тренування (за замовчуванням: 640)
* `--patience` — терпіння для зупинки через EarlyStopping (за замовчуванням: 3)
* `--save_period` — зберігати чекпоінт кожні X епох (за замовчуванням: -1, вимкнено)
* `--resume` — відновлення тренування з останнього збереженого чекпоінту, якщо він існує

**Приклад команди для запуску навчання на всіх 8 класах:**

```bash
python train.py --multi_class --epochs 100 --batch 32 --save_period 1
```

## Обробка відео навченою моделлю

Скрипт передбачає запуск інференсу та трекінгу на відеофайлах. Основні гіперпараметри:

* `--input_file` — шлях до вхідного відеофайлу (обов'язковий параметр)
* `--output_dir` — папка для збереження вихідного відео (за замовчуванням: `'examples'`)
* `--output_file` — назва вихідного відеофайлу (за замовчуванням: `None`, буде використано ім'я вхідного файлу з міткою часу)
* `--model` — шлях до навчених ваг моделі YOLO26 (за замовчуванням: `'weights/best.pt'`)
* `--stride` — обробляти кожен N-й кадр (за замовчуванням: `1`)
* `--conf` — поріг впевненості (за замовчуванням: `0.5`)
* `--iou` — поріг IOU для трекінгу (за замовчуванням: `0.7`)

**Приклад запуску обробки відео:**

```bash
python predict.py --input_file path/to/video.mp4 --model weights/best.pt --iou 0.5 

```

## Validation performance (не є незалежною оцінкою узагальнювальної здатності моделі)

### 1. Базова модель (до fine-tuning):

Під час первинної оцінки базової моделі на валідаційній вибірці було отримано наступні результати:

* **mAP50-95:** 0.4904
* **mAP50:** 0.6354
* **mAP75:** 0.5399
* **Precision:** 0.8189
* **Recall:** 0.7277
* **F1-score:** 0.7706

Базова модель уже має початкові знання для виявлення цільових об'єктів, однак її якість на поточній validation-вибірці є недостатньою для задачі. Значення Recall 0.7277 свідчить про те, що частина об'єктів залишається невиявленою, тоді як Precision 0.8189 характеризує співвідношення коректних детекцій до всіх отриманих позитивних передбачень. Значення mAP50 = 0.6354 та mAP50-95 = 0.4904 показують, що модель потребує адаптації до особливостей цільового датасету.

### 2. Модель після fine-tuning (на 8 класах):
Після завершення навчання (спрацював EarlyStopping на 7-й епосі) досягнуто такі загальні показники:

Показники у загальному форматі *середнє значення ± стандартне відхилення* між 8 класами:

* **mAP50-95:** 0.722
* **mAP50:** 0.902 ± 0.0377
* **Precision (all):** 0.829 ± 0.0794
* **Recall (all):** 0.836 ± 0.0985
* **F1-score (all):** 0.8324
  
*Показники по окремих класах:*

* **Warbler:** Precision 0.747 | Recall 0.956 | mAP50 0.949
* **Finch:** Precision 0.890 | Recall 0.849 | mAP50 0.939
* **Falcon:** Precision 0.879 | Recall 0.872 | mAP50 0.924
* **Canary:** Precision 0.908 | Recall 0.835 | mAP50 0.916
* **Starling:** Precision 0.761 | Recall 0.879 | mAP50 0.907
* **Swiftlet:** Precision 0.706 | Recall 0.935 | mAP50 0.889
* **White-bellied swallow:** Precision 0.808 | Recall 0.713 | mAP50 0.866
* **House Sparrow:** Precision 0.934 | Recall 0.649 | mAP50 0.827 *(найнижчий показник повноти, що впливає на пропуск птахів)*

### Порівняння з базовою моделлю
**mAP50-95:** 0.4904 → 0.722 (**+47.3%**)
**mAP50:** 0.6354 → 0.902 (**+42.0%**)
**Precision:** 0.8189 → 0.829 (**+1.2%**)
**Recall:** 0.7277 → 0.836 (**+14.9%**)
**F1:** 0.7706 → 0.8324 (**+8.0%**)

Таким чином, після донавчання модель стала значно краще знаходити об'єкти та точніше визначати їхні межі, при цьому Recall і F1 помітно зросли, а Precision залишився майже на тому самому рівні. Це свідчить про загальне покращення якості детекції без суттєвого збільшення кількості хибних спрацьовувань на даній вибірці (дана вибірка не є репрезентативним представлення предметної області птахів, а лише наближенням).

Водночас із загальної статистики різко вибивається клас House Sparrow. Його показник Recall становить лише 0.649 (модель пропускає близько 35% горобців). Ця аномалія є головним вузьким місцем поточної версії, що мають потенційні причини:
* Нестача ракурсів: у вибірці може бракувати фотографій горобців з різних боків.
* Специфіка вибірки: приклади з горобцями можуть бути об'єктивно набагато складнішими, ніж з іншими птахами. Якщо це так, то для вирівнювання об'єктивності датасету потрібно ускладнити тренувальні приклади й для інших видів.
* Якість матеріалу: зображення горобців у датасеті можуть мати гіршу роздільну здатність або більше розмиття (motion blur), порівняно з якісними фотографіями інших класів.

## Короткий опис проблем, що виникли, та можливих покращень.

### Виявлені проблеми:
1. **Глітчі та зникнення рамок на відео в реальних умовах:** 
модель періодично втрачає об'єкт на відео. Найбільш яскраво це виражено на найскладнішому класі House Sparrow. Ймовірно, це пов'язано з тим, що базова модель має ширшу генералізацію, тоді як наша версія після fine-tuning зазнала часткового катастрофічного забування загальних ознак або змінила розподіл confidence-скорів через вузьку спеціалізацію. Значною мірою пропуски можуть провокуюватися об'єктивно поганою якістю відео (артефакти стиснення, розмиття).

2. **Плутанина з невідомими видами та сильна залежність від ракурсу:** 
птахи, які не належать до 8 цільових класів, часто хибно розпізнаються як один із відомих моделі видів. Це пояснюється тим, що під час навчання в датасет було додано недостатню кількість фонових зображень сторонніх птахів (з порожніми мітками, тег "null"). Оскільки наша модель є closed-set класифікатором, вона змушена віднести будь-який знайдений об'єкт до одного з 8 доступних їй класів. Додавання фонових зображень (тег "null") до датасету вирішує цю проблему лише частково, оскільки не створює справжнього класу для відхилення (UNKNOWN).

Також детекція критично залежить від пози, на прикладі зі зграєю голубів (яких модель має ігнорувати): алгоритм загалом успішно їх ігнорує, але коли один голуб cтоїть під іншим кутом, модель хибно сприймає його за цільовий клас. Щойно птах змінює позу — рамка знову зникає, як і очікувалося.

3. **Різниця у поведінці багатокласової та "сплюснутої" (`single_cls`) моделей:** при використанні режиму схлопування в один клас (`single_cls=True`) модель формує занадто роздуті рамки або об'єднує кількох близько розташованих птахів в один спільний бокс.

#### Додаткові матеріали (папка examples)
Більше прикладів роботи моделі можна знайти в директорії examples. Серед них:
* canary-good-quality.mp4 (ідеальний кейс): У кадрі присутні дві канарки — одна на передньому плані, інша розмита на фоні. Модель детектує обох птахів з високою точністю. Рамки тримаються стабільно, жодних глітчів не спостерігається.
* canary(rare-not-in-dataset)-good-quality.mp4 (невпевненість між класами): на відео зображений дуже рідкісний вид канарки, якого не було в тренувальному датасеті. Залежно від ракурсу модель вагається, періодично змінюючи класифікацію з Canary на Finch, що яскраво демонструє її логіку на незнайомих підвидах.
* sparrow(worst_metrics)-good-quality.mp4 (Вплив якості на складний клас): вдалий приклад роботи з найскладнішим класом. Завдяки високій якості відео та статичній позі самого птаха рамка тримається значно стабільніше, проте дрібні глітчі все одно присутні, що підтверджує загальну невпевненість моделі в цьому конкретному класі навіть за сприятливих умов.

### Напрямки для подальших покращень:

* **Перехід до більш складного пайплайну**: Для повноцінного production-рішення та усунення проблеми з невідомими видами необхідно змінити архітектуру пайплайну. Найбільш стійкий варіант — розділення задачі на два етапи ( детектор птахів → класифікатор виду з можливістю відхилення у клас UNKNOWN). 
* **Адаптивний інференс:** тонке налаштування порогів (`conf`, `iou`) залежно від якості відео або конкретного розпізнаного підвиду для стабілізації рамок.
* **Збагачення датасету:** додавання зображень птахів із нетипових ракурсів та збільшення варіативності всередині класів (різні кольори, специфічні особливості, підвиди).
